# Greedy: Take the Best Choice Now, Never Look Back

## 🧠 Intuition

A greedy algorithm builds a solution by always making the choice that looks best **right now**,
committing to it, and never reconsidering. When it works, it's beautifully simple and fast. The
hard part isn't writing it — it's **proving the local choice leads to the global optimum**.

> 💡 **Analogy — making change with the fewest coins.** Keep grabbing the largest coin that still
> fits. With standard coin systems (1, 5, 10, 25) this is optimal. But with a weird system (say
> 1, 3, 4) greedy can fail: for 6 it takes 4+1+1 (three coins) when 3+3 (two coins) is better.
> Same algorithm, different coin set — that's why greedy needs *justification*.

So greedy is a gamble that pays off only for problems with the right structure. Recognizing when
it's safe — versus when you need [dynamic programming](06.Dynamic-Programming.md) — is the core
skill of this topic.

## 📐 How It Works

Greedy is correct when a problem has two properties:

1. **Greedy choice property:** a globally optimal solution can be reached by making locally
   optimal choices.
2. **Optimal substructure:** an optimal solution contains optimal solutions to subproblems.

The usual recipe: **sort by some criterion**, then sweep through making the obvious choice.

```mermaid
graph LR
    A["sort by the right key"] --> B["scan once"]
    B --> C["greedily accept/reject each"]
    C --> D["optimal — IF the structure allows"]
```

The classic proof technique is an **exchange argument**: show that any optimal solution can be
transformed into the greedy one without getting worse.

## 🧾 Pseudocode

```
greedy(items):
    sort items by the chosen criterion
    result = []
    for item in items:
        if item is compatible with result:
            result.add(item)
    return result
```

## 💻 C# Implementation

```csharp
// Activity selection: maximum non-overlapping intervals → sort by EARLIEST FINISH time
int MaxActivities(int[][] intervals) {        // intervals: [start, end]
    Array.Sort(intervals, (a, b) => a[1] - b[1]);   // earliest finishing first
    int count = 0, lastEnd = int.MinValue;
    foreach (var iv in intervals)
        if (iv[0] >= lastEnd) { count++; lastEnd = iv[1]; }   // take it, advance
    return count;
}

// Jump Game: can you reach the last index? Track the farthest reachable so far.
bool CanJump(int[] nums) {
    int farthest = 0;
    for (int i = 0; i < nums.Length; i++) {
        if (i > farthest) return false;        // stuck before this index
        farthest = Math.Max(farthest, i + nums[i]);
    }
    return true;
}
```

> Notice the recurring move: **sort by the right key** (earliest finish, not earliest start or
> shortest duration — that specific key is what makes activity selection optimal).

## ⏱️ Complexity

| Typical greedy | Time | Space |
|----------------|------|-------|
| Sort + single sweep | O(n log n) | O(1)–O(n) |
| Sweep only (no sort needed) | O(n) | O(1) |

Greedy is usually much cheaper than the DP alternative — *when it's valid*. The cost is dominated
by the initial sort.

## ⚖️ When to Use It

- **When the greedy choice is provably safe:** interval scheduling, Huffman coding, [Dijkstra](../03-Graphs/04.Shortest-Paths.md),
  [Kruskal/Prim MST](../03-Graphs/05.Minimum-Spanning-Trees.md), fractional knapsack, minimizing
  lateness.
- **Try greedy first** on optimization problems — if you can't find a counterexample and can
  sketch an exchange argument, it's likely right and far simpler than DP.
- **Don't use it when** local optima don't compose into a global one — e.g. **0/1 knapsack**
  (can't take fractions) needs [DP](06.Dynamic-Programming.md); greedy by value/weight ratio fails.

```csharp
// ❌ Sorting by the WRONG key (activity selection by earliest START or shortest DURATION fails)

```

## 🌍 Real-World Applications

- Scheduling (CPU jobs, meeting rooms), bandwidth/resource allocation.

## 🎯 Practice (with full solutions)

### 1. Assign Cookies — `Easy`
**Problem:** Each child has a greed factor; each cookie a size. Maximize satisfied children (a
child is satisfied if cookie size ≥ greed).
**Approach:** Sort both; give the smallest adequate cookie to the least greedy child.
```csharp
int FindContentChildren(int[] g, int[] s) {
    Array.Sort(g); Array.Sort(s);
    int child = 0, cookie = 0;
    while (child < g.Length && cookie < s.Length) {
        if (s[cookie] >= g[child]) child++;   // satisfied
        cookie++;
    }
    return child;
}
```
**Complexity:** O(n log n). **Why this fits:** sort-and-match, the simplest provable greedy.

### 2. Non-overlapping Intervals — `Medium`
**Problem:** Minimum intervals to remove so the rest don't overlap.
**Approach:** Keep the maximum non-overlapping set (sort by end, like activity selection); remove
the rest.
```csharp
int EraseOverlapIntervals(int[][] intervals) {
    Array.Sort(intervals, (a, b) => a[1] - b[1]);
    int keep = 0, lastEnd = int.MinValue;
    foreach (var iv in intervals)
        if (iv[0] >= lastEnd) { keep++; lastEnd = iv[1]; }
    return intervals.Length - keep;
}
```
**Complexity:** O(n log n). **Why this fits:** the canonical earliest-finish greedy and its
exchange-argument logic.

### 3. Jump Game II (minimum jumps) — `Medium`
**Problem:** Fewest jumps to reach the last index.
**Approach:** Greedy BFS-by-levels: track the farthest reachable in the current jump; when you
reach the end of the current range, you must jump (increment), extending the range.
```csharp
int Jump(int[] nums) {
    int jumps = 0, curEnd = 0, farthest = 0;
    for (int i = 0; i < nums.Length - 1; i++) {
        farthest = Math.Max(farthest, i + nums[i]);
        if (i == curEnd) { jumps++; curEnd = farthest; }   // forced to jump
    }
    return jumps;
}
```
**Complexity:** O(n). **Why this fits:** a subtle greedy where the "best choice" is "extend the
reach as far as possible per jump."

### 4. Gas Station — `Medium`
**Problem:** Can you complete a circular route, and from which start? `gas[i]` − `cost[i]` is the
net at station i.
**Approach:** If total gas ≥ total cost, a solution exists. Track a running tank; whenever it goes
negative, no station up to here can be the start — reset the candidate to the next station.
```csharp
int CanCompleteCircuit(int[] gas, int[] cost) {
    int total = 0, tank = 0, start = 0;
    for (int i = 0; i < gas.Length; i++) {
        int net = gas[i] - cost[i];
        total += net; tank += net;
        if (tank < 0) { start = i + 1; tank = 0; }   // restart candidate
    }
    return total >= 0 ? start : -1;
}
```
**Complexity:** O(n). **Why this fits:** an elegant one-pass greedy with a non-obvious correctness
argument — exactly the kind that rewards trying greedy.

## ✅ Key Takeaways

- Greedy makes the locally best choice and never backtracks — simple and fast **when valid**.
- Validity needs the **greedy-choice property** + **optimal substructure**; prove via an
  **exchange argument** or find a counterexample.
- The usual recipe is **sort by the right key, then sweep** — choosing that key is the crux.
- Powers Dijkstra, MST, Huffman, interval scheduling, fractional knapsack.
- **0/1 knapsack and arbitrary coin change break greedy** → use [DP](06.Dynamic-Programming.md).
