# Binary Search: Halve the Search Space Every Step

> One of the most important algorithms in this whole repo. Master it cold — including "binary
> search on the answer."

## 🧠 Intuition

If data is **sorted**, you never need to scan it. Look at the middle: if the target is smaller,
it must be in the left half; if larger, the right half. Each comparison **throws away half** the
remaining elements. A billion elements? ~30 steps.

> 💡 **Analogy — guess the number 1–100.** "Is it ≥ 50?" Every yes/no halves the range. You
> corner the answer in ~7 guesses, not 100.

The idea generalizes far beyond arrays: whenever a yes/no test is **monotonic** ("once it's
true, it stays true"), you can binary-search for the boundary — even when there's no array at
all. That's "binary search on the answer," and it's where the real power is.

## 📐 How It Works

```mermaid
graph LR
    A["lo .......... mid .......... hi"] --> B{target vs a[mid]}
    B -->|smaller| C["search lo..mid-1"]
    B -->|larger| D["search mid+1..hi"]
    B -->|equal| E["found"]
```

The whole difficulty is **boundary correctness**: inclusive vs exclusive bounds, when to do
`mid+1` vs `mid`, and avoiding infinite loops. Pick one template and use it consistently.

## 🧾 Pseudocode

```
binarySearch(a, target):
    lo = 0; hi = n - 1
    while lo <= hi:
        mid = lo + (hi - lo) / 2
        if a[mid] == target: return mid
        if a[mid] < target:  lo = mid + 1
        else:                hi = mid - 1
    return -1
```

## 💻 C# Implementation

### Classic find

```csharp
int BinarySearch(int[] a, int target) {
    int lo = 0, hi = a.Length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;            // overflow-safe midpoint
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

### Lower bound — first index with `a[i] >= target` (the most reusable form)

```csharp
int LowerBound(int[] a, int target) {
    int lo = 0, hi = a.Length;                    // note: hi = n (exclusive)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < target) lo = mid + 1;        // mid too small → go right
        else hi = mid;                            // mid is a candidate → keep it
    }
    return lo;                                     // insertion point
}
```

### Binary search on the answer (the powerful generalization)

```csharp
// Find the smallest x in [lo, hi] for which feasible(x) is true.
// Requires monotonicity: false...false true...true
int BinarySearchAnswer(int lo, int hi, Func<int, bool> feasible) {
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (feasible(mid)) hi = mid;              // mid works → try smaller
        else lo = mid + 1;                        // mid fails → need bigger
    }
    return lo;
}
```

## ⏱️ Complexity

| Operation | Time | Space |
|-----------|------|-------|
| Search / lower bound / on-answer | O(log n) | O(1) iterative |
| Prerequisite: sorting (if not already) | O(n log n) once | — |

Each step halves the range → log₂ n steps. Iterative uses O(1) space; recursive uses O(log n)
stack.

## ⚖️ When to Use It

- **Searching sorted data** — exact match, first/last occurrence, floor/ceiling, insertion point.
- **"Find the minimum/maximum value that satisfies a condition"** — capacity planning, "minimum
  speed/size/time such that it works." If you can write a monotonic `feasible(x)`, binary-search
  it.
- **Avoid when** data is unsorted and you search once (sorting first may not pay off → [linear](01.Linear-Search.md)
  or [hashing](../01-Linear-Structures/06.Hash-Tables.md)).

## 🚫 Common Mistakes

```csharp
// ❌ Overflow on huge indices
int mid = (lo + hi) / 2;            // can overflow
int mid = lo + (hi - lo) / 2;       // ✅

// ❌ Infinite loop from a wrong update (mid not excluded)
//    With `while (lo < hi)` and `hi = mid`, you MUST use `lo = mid + 1` on the other branch.

// ❌ Mixing inclusive/exclusive bounds between templates → off-by-one bugs
//    Pick ONE template (e.g. lower bound with hi = n) and reuse it.
```

## 🌍 Real-World Applications

- Lookups in sorted arrays, DB indexes, `Array.BinarySearch`, version-control `git bisect`.
- Rate limiting / capacity questions ("minimum servers to handle the load").
- Square roots and numeric root-finding (binary search on a continuous answer).

## 🎯 Practice (with full solutions)

### 1. Binary Search — `Easy`
**Problem:** Return the index of `target` in a sorted array, or -1.
**Approach:** The classic template above.
**Complexity:** O(log n). **Why this fits:** the foundation — get the boundaries right.

### 2. Search Insert Position — `Easy`
**Problem:** Return the index where `target` is, or where it would be inserted to stay sorted.
**Approach:** Lower bound — exactly the insertion point.
```csharp
int SearchInsert(int[] a, int target) => LowerBound(a, target);
```
**Complexity:** O(log n). **Why this fits:** shows lower bound's reusable "insertion point" power.

### 3. Find First and Last Position — `Medium`
**Problem:** First and last index of `target` in a sorted array with duplicates.
**Approach:** Lower bound of `target` gives the first; lower bound of `target + 1` minus one
gives the last.
```csharp
int[] SearchRange(int[] a, int target) {
    int first = LowerBound(a, target);
    if (first == a.Length || a[first] != target) return new[] { -1, -1 };
    int last = LowerBound(a, target + 1) - 1;
    return new[] { first, last };
}
```
**Complexity:** O(log n). **Why this fits:** demonstrates building richer queries from lower bound.

### 4. Koko Eating Bananas (binary search on the answer) — `Medium`
**Problem:** Find the **minimum eating speed** `k` so Koko finishes all piles within `h` hours.
**Approach:** `feasible(k)` = "can finish at speed k in ≤ h hours?" is **monotonic** (faster
always works). Binary-search the smallest feasible `k` over `[1, maxPile]`.
```csharp
int MinEatingSpeed(int[] piles, int h) {
    int lo = 1, hi = piles.Max();
    bool CanFinish(int k) {
        long hours = 0;
        foreach (int p in piles) hours += (p + k - 1) / k;   // ceil(p / k)
        return hours <= h;
    }
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (CanFinish(mid)) hi = mid; else lo = mid + 1;
    }
    return lo;
}
```
**Complexity:** O(n log(maxPile)). **Why this fits:** the gateway "search the answer" problem —
no sorted array, yet binary search applies because the feasibility test is monotonic.

## ✅ Key Takeaways

- On sorted data, binary search finds anything in **O(log n)** by halving the range.
- Learn **lower bound** — it powers exact search, insertion point, ranges, floor/ceiling.
- **Binary search on the answer**: if `feasible(x)` is monotonic, search for the boundary even
  without an array.
- Use the overflow-safe midpoint and **commit to one boundary template** to avoid off-by-one bugs.
