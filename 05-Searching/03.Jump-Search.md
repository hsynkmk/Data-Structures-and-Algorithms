# Jump Search: Leap in Blocks, Then Walk

## 🧠 Intuition

On a sorted array, instead of stepping one element at a time ([linear](01.Linear-Search.md)) or
halving ([binary](02.Binary-Search.md)), jump ahead in fixed-size blocks until you overshoot the
target, then walk backward (linearly) through that one block. The sweet-spot block size is
**√n**, giving **O(√n)** — between linear and binary.

> 💡 **Analogy — flipping through a dictionary in chunks.** You flip ~20 pages at a time until you
> pass your word, then page back one at a time within that chunk.

It's mostly of theoretical/educational interest, but it shines in one niche: systems where
**jumping forward is cheap but jumping backward is expensive** (binary search jumps both ways).

## 📐 How It Works

`n = 16` → block size 4. Jump to indices 0, 4, 8, … until `a[block] >= target`, then linear-scan
the previous block.

## 🧾 Pseudocode

```
step = floor(sqrt(n)); prev = 0
while a[min(step, n)-1] < target:
    prev = step; step += floor(sqrt(n))
    if prev >= n: return -1
for i in prev .. min(step, n)-1:
    if a[i] == target: return i
return -1
```

## 💻 C# Implementation

```csharp
int JumpSearch(int[] a, int target) {
    int n = a.Length;
    int step = (int)Math.Sqrt(n);
    int prev = 0;
    while (prev < n && a[Math.Min(step, n) - 1] < target) {   // jump blocks
        prev = step;
        step += (int)Math.Sqrt(n);
        if (prev >= n) return -1;
    }
    for (int i = prev; i < Math.Min(step, n); i++)            // walk the block
        if (a[i] == target) return i;
    return -1;
}
```

## ⏱️ Complexity

| Case | Time | Space |
|------|------|-------|
| Worst | O(√n) | O(1) |

With block size √n, you do ~√n jumps + ~√n in-block steps = O(√n). Slower than binary's O(log n),
faster than linear's O(n).

## ⚖️ When to Use It

- **Sorted data on media where backward seeks are costly** (some tape/SSD/linked structures) —
  jump search only steps forward then does one small backward scan.
- **Otherwise prefer [binary search](02.Binary-Search.md)** — O(log n) beats O(√n).

## 🚫 Common Mistakes

```csharp
// ❌ Forgetting Math.Min(step, n) → index past the end on the last block
// ❌ Block size other than √n → suboptimal (linear-ish or many in-block steps)
```

## 🌍 Real-World Applications

- Searching sorted data where forward access is much cheaper than random access.
- A teaching stepping-stone between linear and binary search.

## 🎯 Practice (with full solutions)

### 1. Search in a sorted array — `Easy`
**Problem:** Find `target` using jump search.
**Approach:** The implementation above.
**Complexity:** O(√n). **Why this fits:** the direct application.

### 2. First element ≥ target — `Medium`
**Problem:** Find the first element not less than `target`.
**Approach:** Jump to the first block whose end ≥ target, then linear-scan for the first
qualifying element.
```csharp
int FirstAtLeast(int[] a, int target) {
    int n = a.Length, step = (int)Math.Sqrt(n), prev = 0;
    while (prev < n && a[Math.Min(step, n) - 1] < target) { prev = step; step += (int)Math.Sqrt(n); }
    for (int i = prev; i < Math.Min(step, n); i++) if (a[i] >= target) return i;
    return -1;
}
```
**Complexity:** O(√n). **Why this fits:** adapts the block idea to a boundary query.

## ✅ Key Takeaways

- Jump by **√n** blocks, then linear-scan one block → **O(√n)**.
- A middle ground between linear and binary search; rarely optimal.
- Its niche: **forward jumps cheap, backward seeks expensive**.
