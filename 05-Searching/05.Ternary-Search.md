# Ternary Search: Split in Three (and Find Peaks)

## 🧠 Intuition

Ternary search splits the range into **three** parts using two midpoints instead of [binary
search](02.Binary-Search.md)'s one. On a sorted array it's *worse* than binary search (more
comparisons per step). Its real value is elsewhere: finding the **maximum or minimum of a
unimodal function** — one that rises then falls (or falls then rises), with a single peak.

> 💡 **Analogy — finding the top of a hill in fog.** You can't see the summit, but you can sample
> two points. If the left sample is higher, the peak is to the left of the right sample, so you
> discard the far-right third. Repeat, shrinking toward the peak.

For plain sorted-array search, **use binary search**. For peak-finding on a unimodal shape,
ternary search (or a clever binary search) is the tool.

## 📐 How It Works

Pick `m1 = lo + (hi-lo)/3` and `m2 = hi - (hi-lo)/3`. For a function with a single maximum:
- if `f(m1) < f(m2)`, the peak is in `[m1, hi]` → set `lo = m1 + 1`.
- else the peak is in `[lo, m2]` → set `hi = m2 - 1`.

```mermaid

    A["lo .. m1 .. m2 .. hi"] --> B{f(m1) vs f(m2)}
    B -->|f m1 < f m2| C["keep right two-thirds"]
    B -->|else| D["keep left two-thirds"]
```

## 🧾 Pseudocode

```
# maximize a unimodal f over integer range [lo, hi]
while lo < hi:
    m1 = lo + (hi - lo) / 3
    m2 = hi - (hi - lo) / 3
    if f(m1) < f(m2): lo = m1 + 1
    else:             hi = m2 - 1
return lo     # peak position
```

## 💻 C# Implementation

```csharp
// Find the index maximizing a unimodal function f over [lo, hi]
int TernarySearchMax(int lo, int hi, Func<int, double> f) {
    while (lo < hi) {
        int m1 = lo + (hi - lo) / 3;
        int m2 = hi - (hi - lo) / 3;
        if (f(m1) < f(m2)) lo = m1 + 1;     // discard left third
        else hi = m2 - 1;                    // discard right third
    }
    return lo;
}

// (Sorted-array variant exists but binary search is strictly better — prefer that.)
```

## ⏱️ Complexity

| Operation | Time | Space |
|-----------|------|-------|
| Unimodal peak / sorted search | O(log₃ n) ≈ O(log n) | O(1) |

Same asymptotic class as binary search, but with **more function evaluations per step** — so for
a sorted array binary search wins on constants. The win is conceptual: it handles unimodal
*functions*, not just sorted values.

## ⚖️ When to Use It

- **Optimizing a unimodal function** (single peak/valley): physics simulations, parameter tuning,
  geometry problems, "maximize profit / minimize cost" with one turning point.
- **Not for plain sorted-array search** → [binary search](02.Binary-Search.md) is better.

## 🚫 Common Mistakes

```csharp
// ❌ Applying it to a non-unimodal function → it can converge to the wrong point
//    The function MUST have a single peak/valley over the range.

// ❌ Using it for ordinary sorted-array lookups (slower constants than binary search)
```

## 🌍 Real-World Applications

- Numerical optimization of unimodal cost/profit curves.
- Computational geometry (e.g. closest point on a convex curve).
- Hyperparameter tuning where the metric is single-peaked.

## 🎯 Practice (with full solutions)

### 1. Peak Index in a Mountain Array — `Medium`
**Problem:** An array increases then decreases; return the peak index.
**Approach:** Ternary search (or binary search on the slope). The array is unimodal, so compare
midpoints and discard a third.
```csharp
int PeakIndexInMountainArray(int[] a) {
    int lo = 0, hi = a.Length - 1;
    while (lo < hi) {                       // binary-search the slope (cleaner here)
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < a[mid + 1]) lo = mid + 1;   // still ascending → peak is right
        else hi = mid;                            // descending → peak is here or left
    }
    return lo;
}
```
**Complexity:** O(log n). **Why this fits:** the quintessential unimodal-peak problem (note
binary-on-slope is the common clean solution).

### 2. Maximize a unimodal function — `Medium`
**Problem:** Find the integer `x` in `[0, N]` maximizing `f(x) = -(x-7)² + 50`.
**Approach:** `TernarySearchMax(0, N, f)` — the parabola is unimodal with peak at 7.
```csharp
int x = TernarySearchMax(0, 100, v => -(v - 7) * (v - 7) + 50);   // returns 7
```
**Complexity:** O(log N). **Why this fits:** the pure use case — optimizing a single-peaked
function with no array involved.

## ✅ Key Takeaways

- Ternary search splits into **three**; same O(log n) class but more comparisons than binary.
- Its real strength is finding the **peak/valley of a unimodal function**, not sorted-array search.
- The function/array **must be unimodal**, or it can converge wrongly.
- For ordinary sorted lookups, choose [binary search](02.Binary-Search.md).
