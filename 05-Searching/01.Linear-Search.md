# Linear Search: Check Every Element

## 🧠 Intuition

The simplest possible search: look at each element in turn until you find what you want (or run
out). No assumptions about the data — it doesn't need to be sorted.

> 💡 **Analogy — looking for a friend in an unsorted crowd.** You have no choice but to scan face
> by face. If the crowd were lined up by height, you could be smarter — but unsorted means you
> check everyone.

It's the baseline every other search algorithm tries to beat. Sometimes it *is* the right
answer: for small or unsorted data, its simplicity wins.

## 📐 How It Works

`[4, 2, 7, 1, 9]`, target 7: check 4 (no), 2 (no), 7 (yes!) → return index 2.

## 🧾 Pseudocode

```
for i in 0 .. n-1:
    if a[i] == target: return i
return -1     # not found
```

## 💻 C# Implementation

```csharp
int LinearSearch(int[] a, int target) {
    for (int i = 0; i < a.Length; i++)
        if (a[i] == target) return i;
    return -1;
}
```

## ⏱️ Complexity

| Case | Time | Space |
|------|------|-------|
| Best (first element) | O(1) | O(1) |
| Average / Worst | O(n) | O(1) |

No setup, no sorting requirement — but linear in the worst case.

## ⚖️ When to Use It

- **Unsorted data**, or data you can only stream once.
- **Small inputs** where the simplicity beats setting up something fancier.
- When you'd search **once** — sorting first (O(n log n)) to enable [binary search](02.Binary-Search.md)
  only pays off across many searches.
- For repeated lookups, prefer a [hash table](../01-Linear-Structures/06.Hash-Tables.md) (O(1)
  average) or sort + binary search.

## 🚫 Common Mistakes

```csharp
// ❌ Returning the value instead of the index when the caller needs position
// ❌ Off-by-one: i <= a.Length runs past the end
for (int i = 0; i < a.Length; i++)   // ✅
```

## 🌍 Real-World Applications

- Searching tiny or one-off collections; scanning a log line by line.
- Finding an element by a predicate (`List.Find`) when no index exists.

## 🎯 Practice (with full solutions)

### 1. Find an element / first occurrence — `Easy`
**Problem:** Return the index of `target`, or -1.
**Approach:** The loop above.
**Complexity:** O(n). **Why this fits:** the baseline.

### 2. Find the maximum — `Easy`
**Problem:** Return the largest value (a linear scan tracking the best so far).
```csharp
int Max(int[] a) {
    int best = a[0];
    for (int i = 1; i < a.Length; i++) if (a[i] > best) best = a[i];
    return best;
}
```
**Complexity:** O(n). **Why this fits:** the "single pass, track best" pattern underlies many
problems.

### 3. Two Sum (unsorted) — `Easy`
**Problem:** Find indices summing to `target`. Linear search is O(n²); beat it.
**Approach:** A [hash table](../01-Linear-Structures/06.Hash-Tables.md) turns the inner linear
search into an O(1) lookup → O(n) overall.
```csharp
int[] TwoSum(int[] a, int target) {
    var seen = new Dictionary<int, int>();
    for (int i = 0; i < a.Length; i++) {
        if (seen.TryGetValue(target - a[i], out int j)) return new[] { j, i };
        seen[a[i]] = i;
    }
    return Array.Empty<int>();
}
```
**Complexity:** O(n). **Why this fits:** shows when to *replace* linear search with hashing.

## ✅ Key Takeaways

- Linear search scans element by element: **O(n)**, no sorting needed.
- It's the right tool for **small/unsorted/one-off** searches.
- For repeated lookups, a sorted array + [binary search](02.Binary-Search.md) or a hash table beats it.
