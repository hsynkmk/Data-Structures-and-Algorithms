# Bit Manipulation: Working Directly with the 1s and 0s

## 🧠 Intuition

Every integer is stored as a row of bits (binary digits). Normally you think in decimal and
let the computer worry about bits. **Bit manipulation** is when you operate on those bits
*directly* — and it's often dramatically faster and more compact than the obvious approach.

> 💡 **Analogy — a row of light switches.** A 32-bit integer is 32 switches, each on (1) or off
> (0). Bit operations let you flip, test, and combine whole rows of switches in a single CPU
> instruction. Want to track which of 32 features a user has enabled? One integer, one switch
> per feature — instead of 32 booleans.

You don't need bit tricks every day, but they unlock elegant solutions to a specific family of
problems (subsets, toggles, "find the unique element") and show up in DP state compression,
hashing, and low-level systems code.

## 📐 How It Works

The operators (shown on 4-bit numbers for clarity):

| Op | Name | Example | Result | Meaning |
|----|------|---------|--------|---------|
| `&` | AND | `1100 & 1010` | `1000` | 1 only where **both** are 1 |
| `\|` | OR | `1100 \| 1010` | `1110` | 1 where **either** is 1 |
| `^` | XOR | `1100 ^ 1010` | `0110` | 1 where bits **differ** |
| `~` | NOT | `~1100` | `0011`* | flip every bit |
| `<<` | left shift | `0011 << 1` | `0110` | shift up = ×2 |
| `>>` | right shift | `0110 >> 1` | `0011` | shift down = ÷2 |

\*`~` on a real `int` flips all 32 bits, so `~12` is actually `-13` in two's complement — be
careful with sign.

### The essential idioms

```
Test bit i:        (x >> i) & 1          → 1 if set, else 0
Set bit i:         x | (1 << i)
Clear bit i:       x & ~(1 << i)
Toggle bit i:      x ^ (1 << i)
Is x a power of 2: x > 0 && (x & (x - 1)) == 0
Lowest set bit:    x & (-x)
Remove lowest set bit: x & (x - 1)
```

Why `x & (x-1)` clears the lowest set bit: subtracting 1 flips the lowest 1 to 0 and all the
0s below it to 1; ANDing wipes that whole tail. Repeatedly doing this counts set bits.

### The XOR superpower

XOR has magic properties: `x ^ x = 0` and `x ^ 0 = x`. So XOR-ing a list where every value
appears twice except one **cancels the pairs and leaves the loner**:

```
4 ^ 1 ^ 2 ^ 1 ^ 2 = 4   (the 1s cancel, the 2s cancel)
```

## 🧾 Pseudocode

```
count_set_bits(x):
    count = 0
    while x != 0:
        x = x & (x - 1)     # remove lowest set bit
        count += 1
    return count

iterate_all_subsets_of_n_items(n):
    for mask in 0 .. (2^n - 1):     # each mask is one subset
        for i in 0 .. n-1:
            if (mask >> i) & 1:     # item i is in this subset
                use item i
```

## 💻 C# Implementation

```csharp
// Count set bits (population count) — O(number of set bits)
int CountBits(int x) {
    int count = 0;
    while (x != 0) { x &= (x - 1); count++; }
    return count;
}
// (.NET 6+: System.Numerics.BitOperations.PopCount((uint)x) does this in hardware.)

// Is x a power of two?
bool IsPowerOfTwo(int x) => x > 0 && (x & (x - 1)) == 0;

// The lonely number: every element appears twice except one
int SingleNumber(int[] nums) {
    int acc = 0;
    foreach (int n in nums) acc ^= n;   // pairs cancel
    return acc;
}

// Enumerate every subset of a set of size n using bitmasks
void PrintSubsets(int[] items) {
    int n = items.Length;
    for (int mask = 0; mask < (1 << n); mask++) {     // 1<<n == 2^n
        var subset = new List<int>();
        for (int i = 0; i < n; i++)
            if ((mask >> i & 1) == 1) subset.Add(items[i]);
        Console.WriteLine("{" + string.Join(",", subset) + "}");
    }
}
```

## ⏱️ Complexity

| Operation | Time | Note |
|-----------|------|------|
| Any single bitwise op (`&`,`\|`,`^`,`<<`,`>>`) | O(1) | One CPU instruction |
| Count set bits via `x & (x-1)` | O(set bits) | At most O(word size) = O(32) |
| Enumerate all subsets of n items | O(n · 2ⁿ) | 2ⁿ masks, n bits each |

Bitmask subset enumeration is why bit manipulation pairs with DP: you can encode a *set of up
to ~20 items* as a single integer and use it as a DP key ("bitmask DP").

## ⚖️ When to Use It

- **Great for:** flags/permissions in one integer, set membership over a small universe,
  "appears once" problems, power-of-two checks, generating subsets, squeezing DP state.
- **Avoid for:** general arithmetic where clarity matters — `x << 1` instead of `x * 2` is
  rarely worth the confusion in modern code (the compiler optimizes anyway).
- **Watch the sign:** use `uint`/`long` and right-shift carefully; `~` and `>>` behave
  differently on negative numbers (arithmetic vs logical shift).

## 🚫 Common Mistakes

```csharp
// ❌ Operator precedence: & is LOWER than == in C#
if (x & 1 == 0) { }          // parses as x & (1 == 0) → compile error / wrong logic
// ✅ Parenthesize bit tests
if ((x & 1) == 0) { }        // "x is even"

// ❌ Shifting by >= the type's width is undefined-ish (mod 32 for int)
int bad = 1 << 35;           // actually shifts by 35 % 32 = 3, not what you meant
// ✅ Use long, or keep shift amounts in range
long ok = 1L << 35;
```

Other traps: forgetting `~` produces a negative number; assuming `>>` zero-fills on signed
types (it sign-extends — use `>>>` unsigned shift in newer C#, or cast to `uint`).

## 🌍 Real-World Applications

- **Permission/feature flags:** Unix file permissions (`rwx`), bitfield configs.
- **Graphics & hashing:** color channel packing, bloom filters, hash mixing.
- **Bitmask DP:** Traveling Salesman over ≤20 cities, assignment problems.
- **Compression & networking:** packing many small fields into one word.

## 🎯 Practice (with full solutions)

### 1. Single Number — `Easy`
**Problem:** Every element appears twice except one. Find it, in O(1) space.
**Approach:** XOR everything; pairs cancel to 0, leaving the unique value.
```csharp
int SingleNumber(int[] nums) {
    int acc = 0;
    foreach (int n in nums) acc ^= n;
    return acc;
}
```
**Complexity:** O(n) time, O(1) space. **Why this fits:** the textbook use of XOR's
self-cancelling property — no hash set needed.

### 2. Number of 1 Bits — `Easy`
**Problem:** Count the set bits in an unsigned integer (Hamming weight).
**Approach:** Repeatedly clear the lowest set bit with `x & (x-1)` and count the iterations.
```csharp
int HammingWeight(uint n) {
    int count = 0;
    while (n != 0) { n &= n - 1; count++; }
    return count;
}
```
**Complexity:** O(number of set bits). **Why this fits:** demonstrates the `x & (x-1)` idiom
that loops only as many times as there are 1s.

### 3. Counting Bits 0..n — `Medium`
**Problem:** For every number from `0` to `n`, return its set-bit count.
**Approach:** DP on bits: `bits[i] = bits[i >> 1] + (i & 1)` — `i` has the same bits as `i/2`
plus its own lowest bit. (Ties bit tricks to [DP](../06-Algorithm-Paradigms/06.Dynamic-Programming.md).)
```csharp
int[] CountBitsUpTo(int n) {
    var bits = new int[n + 1];
    for (int i = 1; i <= n; i++)
        bits[i] = bits[i >> 1] + (i & 1);
    return bits;
}
```
**Complexity:** O(n) time, O(n) space — beats counting each number independently.
**Why this fits:** shows a bit *recurrence* powering a clean DP.

### 4. Subsets via bitmask — `Medium`
**Problem:** Generate the power set of `nums` using bitmasks (no recursion).
**Approach:** Each integer `mask` in `[0, 2ⁿ)` encodes one subset; bit `i` set ⇒ include `nums[i]`.
```csharp
IList<IList<int>> Subsets(int[] nums) {
    int n = nums.Length;
    var result = new List<IList<int>>();
    for (int mask = 0; mask < (1 << n); mask++) {
        var sub = new List<int>();
        for (int i = 0; i < n; i++)
            if ((mask >> i & 1) == 1) sub.Add(nums[i]);
        result.Add(sub);
    }
    return result;
}
```
**Complexity:** O(n · 2ⁿ). **Why this fits:** the iterative twin of the recursive subset
generator from [Recursion](03.Recursion.md) — same idea, bits instead of branches.

## ✅ Key Takeaways

- Master the six operators and the test/set/clear/toggle idioms — they're O(1) building blocks.
- `x & (x-1)` removes the lowest set bit; `x & (x-1) == 0` tests power-of-two.
- **XOR cancels pairs** — the key to "find the unique element" with O(1) space.
- A bitmask encodes a small set in one integer — the basis of subset enumeration and bitmask DP.
- Always **parenthesize** bit tests (`&`/`|` have low precedence) and mind sign with `~`/`>>`.

2. Why does XOR-ing a list with all-but-one duplicates leave the unique value?
3. What does `x & (x - 1)` do, and how does it help count set bits?
